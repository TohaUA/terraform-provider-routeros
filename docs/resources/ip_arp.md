# routeros_ip_arp (Resource)


This resource manages **static, non-DHCP** IPv4 ARP entries under `/ip/arp`. Dynamic entries learned on the wire and entries created dynamically by DHCP leases are intentionally rejected during import, refresh, update, and delete.

When the same IPv4 address appears on multiple interfaces, import with `<address>,<interface>` (or the RouterOS `.id`); bare `<address>` imports fail if more than one entry matches.

## Adopting Script- or Scheduler-Managed Entries

If static `/ip/arp` rows were previously maintained by an on-device RouterOS scheduler or script:

1. Declare matching `routeros_ip_arp` blocks in Terraform configuration.
2. Import each static row using `<address>,<interface>` or its RouterOS `.id`.
3. Run `terraform plan` and confirm no unexpected changes are planned.
4. Disable or remove the RouterOS scheduler/script so both systems do not overwrite the same table.

Unlike an on-device RouterOS scheduler that runs periodically on a timer, Terraform reconciles `/ip/arp` only when `terraform apply` (or a scheduled workflow run) is executed.

---

## Example Usage
```terraform
resource "routeros_ip_arp" "example" {
  address     = "192.0.2.50"
  interface   = "ether2"
  mac_address = "00:11:22:33:44:55"
  comment     = "Static ARP entry"
}
```

## Schema

### Required

- `address` (String) The IPv4 address to be mapped.
- `interface` (String) Name of the interface.

### Optional

- `comment` (String)
- `disabled` (Boolean)
- `mac_address` (String) MAC address to map to the IPv4 address.
- `published` (Boolean) Static proxy-ARP entry for an individual IP address. When an ARP query is received for the specific IP address, the device will respond with its own MAC address.

### Read-Only

- `complete` (Boolean) Whether the ARP entry is complete.
- `dhcp` (Boolean) Whether the ARP entry was created by DHCP.
- `dynamic` (Boolean) Configuration item created by software, not by management interface. It is not exported, and cannot be directly modified.
- `id` (String) The ID of this resource.
- `invalid` (Boolean)
- `status` (String) Current ARP entry status reported by RouterOS (for example `permanent`, `reachable`, `stale`, or `failed`).

## Import
Import is supported using the following syntax:
```shell
# Import by RouterOS internal ID:
terraform import routeros_ip_arp.example "*1"

# Import by address and interface (recommended when the same IPv4 address exists on multiple interfaces):
terraform import routeros_ip_arp.example "192.0.2.50,ether2"

# Or using explicit attribute filters:
terraform import routeros_ip_arp.example "address=192.0.2.50,interface=ether2"
```
